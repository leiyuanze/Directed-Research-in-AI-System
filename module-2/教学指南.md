### 第 3 步：写 `read_rgbd_and_pose`

找到 `hw.ipynb` 里第一个代码单元格：

```python
def read_rgbd_and_pose(data_root):
```

把它替换成：

```python
CAM_FLIP = np.diag([1.0, -1.0, -1.0, 1.0])
FIX_CAMERA = True


def read_rgbd_and_pose(data_root):
    data_root = Path(data_root)

    # 1. 读 camera.json
    with open(data_root / 'camera.json', 'r', encoding='utf-8') as f:
        camera = json.load(f)

    # 2. K 是 3x3，补成 4x4，方便和 pose 统一形状
    K = np.asarray(camera['K'], dtype=np.float64)
    K4 = np.eye(4, dtype=np.float64)
    K4[:3, :3] = K

    # 3. 按 0000, 0001, ... 排序，跳过 K
    keys = sorted(k for k in camera.keys() if k != 'K')

    poses, intrinsics, rgbs, depths = [], [], [], []

    for key in keys:
        # 4. 读 4x4 pose
        pose = np.asarray(camera[key], dtype=np.float64)

        # 5. 修正相机坐标：绕相机局部 x 轴旋转 180 度
        #    这一步等价于把 y 和 z 两个轴同时反向
        if FIX_CAMERA:
            pose = pose @ CAM_FLIP

        # 6. 读 RGB：RGBA -> RGB，丢掉 alpha
        rgb_path = data_root / 'color' / f'{key}.png'
        rgb = np.asarray(Image.open(rgb_path).convert('RGB'))

        # 7. 读 depth：uint16 毫米 -> float32 米
        depth_path = data_root / 'depth' / f'{key}.png'
        depth = np.asarray(Image.open(depth_path)).astype(np.float32) / 1000.0

        poses.append(pose)
        intrinsics.append(K4.copy())
        rgbs.append(rgb)
        depths.append(depth)

    return poses, intrinsics, rgbs, depths
```

逐行理解：

- `camera['K']` 是内参，3×3。
- `K4[:3, :3] = K` 的意义：后面 starter 打印的是 `(4,4)`，而且 `MeshExtractor` 只取前 3×3 的元素 `fx, fy, cx, cy`。
- `keys = sorted(...)`：保证图像和 pose 一一对应，顺序是 `0000`、`0001`、……、`0099`。
- `pose @ CAM_FLIP`：注意是右乘，表示在**相机局部坐标系**里绕 x 轴旋转 180°。左乘是绕世界 x 轴，结果不对。
- `convert('RGB')`：颜色图有 alpha 通道，Open3D 需要 3 通道。
- `astype(np.float32) / 1000.0`：把毫米转成米。不转的话深度会大 1000 倍，TSDF 完全错位。
- `RGBA` 里的背景 alpha=0，但 RGB 仍然有值。Open3D 的 TSDF 用 depth 中的 0 作为无效深度，所以背景不会参与融合。

### 第 7 步：TSDF 超参数实验

`MeshExtractor` 的默认值是：

```python
depth_trunc=3.0, sdf_trunc=0.02, voxel_size=0.004
```

四个参数的含义：

- `voxel_size`：TSDF 体素边长。越小越细，但内存和时间增加；太大细节丢失。建议试 `0.002 / 0.004 / 0.008 / 0.016`。
- `sdf_trunc`：SDF 截断距离。一般取 `3~5 × voxel_size`；太小会破洞，太大会过度平滑、产生厚壳。建议试 `0.01 / 0.02 / 0.04`。
- `depth_trunc`：超过这个深度的像素不融合。物体半径约 3 m，建议试 `2.5 / 3.0 / 3.5 / 4.0`。太小会切掉物体，太大会引入背景噪声。
- 视角数：从 `5 / 10 / 25 / 50 / 100` 里选几个。视角越多，空洞越少，但 25 以后收益变小。

写一个循环时，不要一次跑几百组。先固定其他三个参数，只改一个，记录：

```text
views, voxel_size, sdf_trunc, depth_trunc, time, vertices, triangles, chamfer_mm, 现象
```

你已经验证过的视角结果可以直接引用：

| 视角数 | Chamfer / mm |
| ---: | ---: |
| 5 | 30.27 |
| 10 | 6.72 |
| 25 | 4.69 |
| 50 | 3.87 |
| 100 | 3.57 |

报告里要写“为什么会这样”，而不是只贴数字：

- 5 视角时很多表面没被观测到，TSDF 只有少量约束，出现空洞和错误拼接。
- 视角增多后，同一表面被多次观测，加权平均降低了深度噪声。
- 25 视角以后，大部分表面已经被覆盖，新增视角带来的信息变少，所以收益递减。
- `voxel_size` 变小，细节提升但噪声和内存也上升；达到深度图噪声尺度以后，再小没有意义。
- `sdf_trunc` 太大时，不同表面的零水平集互相干扰，会把薄结构糊在一起。

### 第 3 步：理解模型做了什么

Omnidata DPT-Hybrid 384 的流程：

1. 把图片 resize 到短边 384，再 center crop 到 384×384。
2. 转成 tensor，归一化到 `mean=0.5, std=0.5`，即输入范围约 `[-1, 1]`。
3. 编码器：ResNet-50 + ViT-B/16 hybrid backbone，输出多尺度特征。
4. DPT 解码器融合多尺度特征，输出 384×384 的预测。
5. depth 分支输出 1 通道 inverse depth，官方 demo 会：
   - `clamp(0, 1)`
   - 上采样到 512×512
   - `1 - output`，变成“越大越远”的可视化
6. normal 分支输出 3 通道，对应法线的 x/y/z 分量，映射到 [0,1] 后用 RGB 显示。

重点：**depth 模型输出的是相对深度/逆深度，不是米制深度。** 所以不能直接说“这里是 2.5 米”，只能做相对远近和结构分析。报告里要明确这一点。

- normal 表现：能勾出人物轮廓和排线方向，但很多区域是噪声，不能当作真实表面法线。
- 原因：Omnidata 的训练数据主要来自 3D 扫描/合成场景的真实 RGB，而不是线稿。模型依赖 shading、texture、perspective 等自然图像线索；线稿把 shading 和材质信息去掉了，所以 depth 失效。
- 改进：加入线稿/素描域的 fine-tune 数据；使用能跨域泛化的更强模型；用语义分割先分出人物和背景；用多视角或已知尺度的辅助信息。

示例：`outdoor_real.jpg`

- 领域：真实室外，逆光、强曝光、人物与云层边界。
- depth 表现：人物区域接近一整块，背景云层没有层次，说明模型把逆光当成了主要线索。
- normal 表现：能给出一些表面朝向，但边界不稳定。
- 原因：逆光和过曝破坏了 shading 和 texture 线索；训练数据中这种极端曝光的样本占比可能低。
- 改进：曝光归一化/多曝光融合；在逆光数据上 fine-tune；使用对光照更鲁棒的模型；结合语义先验。

### 第 5 步：更强模型的综述

作业要求“找一个优于 Omnidata 的单目深度模型，并概述它如何提升深度估计”。推荐写 **Depth Anything V2（2024）**。

- 出处：Lihe Yang et al., *Depth Anything V2*, 2024。
- 核心思路：用高质量合成数据训练一个强大的 teacher，再在大量无标签真实图像上生成伪标签，训练轻量 student。
- 结构：DINOv2 编码器 + 多尺度 DPT 解码器。
- 相比 Omnidata 的优势：
  - 训练数据规模和多样性大得多，跨域泛化更强。
  - 合成数据提供精确的几何监督，真实伪标签提供开放域覆盖。
  - 对细结构、透明/反射/低纹理区域的鲁棒性更好。
  - 提供 relative depth 和 metric depth 两类模型，后者可以直接输出米制深度。
- 报告写法：先写 Omnidata 的局限（相对深度、训练域偏自然 RGB、线稿/逆光失败），再写 Depth Anything V2 如何用“合成 teacher + 真实 pseudo-label student”解决跨域和细节问题，最后写一句“可选：如果允许下载权重，可以在失败案例上做定性对比”。

注意：当前 Gradescope 的 10 分 rubric 里，**跑 Depth Anything V2 是可选扩展，不跑不影响分数；但“准确概述一个更强模型”是 Task 1 报告 4 分里的 1 分，不能省。**
